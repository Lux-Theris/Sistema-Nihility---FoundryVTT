# Combate: iniciativa, dano no chat, Vida 0, Contágio, ambiente, radiação, HUD, avisos, Fim do combate, Desfazer uso e Deslocamento

> Parte do guia do projeto. O índice e as regras que valem em todo lugar estão no `CLAUDE.md` da raiz. Quando o texto diz "abaixo"/"acima" ou cita uma seção que não está aqui, procure-a pelo índice.

## Combate: iniciativa, aplicar dano e Condições no HUD

**Iniciativa** (`module/combat/combat.js`): Foundry's `CONFIG.Combat.initiative.formula` is a **global string** — it has no idea who is rolling, so it can't express a pool that depends on each Actor's attribute. The per-document route is the one taken here: `registerInitiative()` (on `init`) swaps `CONFIG.Combatant.documentClass` for a subclass overriding `_getInitiativeFormula()`, which returns the exact same `Nd20 + fixo` as any other attribute roll (`buildAttributeRollFormula`, `dice.js`), item bonus included as a flat add. It extends `CONFIG.Combatant.documentClass` rather than the global class **specifically so it chains** with any module that already replaced it, instead of trampling it. Which attribute governs is the `initiativeAttribute` setting (default Destreza); Nave/Veículo has no combat attributes and falls back to the core formula rather than inventing a pool that type of Actor doesn't have. `rollInitiativeForActor(actor)` is the sheet button's entry point — a player whose character isn't in the combat yet gets a "ask the GM" notice instead of a permission error, since adding a combatant is a GM action.

**Aplicar dano pelo chat** (`module/combat/damage-apply.js`): the system computes damage and posts it; HP only moves when someone clicks. `damageApplyFlags(targetActor, finalDamage)` is called by whoever posts the roll and stores target + already-reduced amount **in the message flags, never in the DOM**, so anyone opening the chat later — or reloading — sees the same card state as whoever was online. `renderDamageControls` then draws Aplicar / Metade / Dobro, GM-only (applying damage to someone else's sheet needs write permission; showing the button to someone who can't use it would only produce errors). After a click the buttons are **replaced** by a Desfazer, because applying twice by accident is invisible — the HP just drops further. Undo restores the exact previous HP saved in the flag, rather than adding the amount back, which would be wrong if anything else touched the HP in the meantime. The personal Escudo (`attributes.shield.value`) absorbs first: `splitShieldDamage` (pure, tested) takes from the Escudo until it is empty and only the rest reaches Vida; Metade/Dobro scale the whole amount before that split, the card reports "X no Escudo · Y na Vida", and Desfazer restores both saved values. A card whose flag carries `absolute: true` (`damageApplyFlags(target, dmg, {absolute})`, for the planned Dano Absoluto) skips the Escudo. Cards applied before this change have no `previousShield` and undo only the HP, as they always did. Nave/Veículo is deliberately not handled here: the damage cascade already writes itself.

**Card de área com botões (L10, 1.65.0).** `rollSkillDamageArea` used to only *list* each target's number, applied by hand. It now stores one `damageApplyFlags` entry per Personagem target (plus `name`) in the flag `damageApplyMany.entries`; `renderDamageControls` draws a row per target (Aplicar/½/×2 → ✓ + ↩) and group actions on top: "Aplicar em todos", "Aplicar aos selecionados" (entries whose `targetUuid` is a controlled Token's actor) and "Desfazer todos". Single-target and area share `applyHit(state, factor)`/`undoHit(state)` — the card writes its flag once after the loop. Area entries carry `noBodyPart: true` (area damage still never lands on a body part), and triggered Conditions now apply on the click, as in single target. Ships in an area are unchanged (their cascade writes itself).

**Vida 0: Caído e Inconsciente** (`module/combat/incapacitation.js`, pure rules in `incapacitation-rules.js`, tested; `FEATURES.incapacitation`, on, options `deathRounds` 3, `wakeRounds` 3, `npcDiesAtZero`). Flow decided with the owner: a PC reaching 0 Vida gets **Caído** with a death counter; at 0 the GM is **warned** (with a "Marcar como morto" button) — the system never kills by itself; "Estabilizar" on the fall card stops the counter. An NPC — `system.isPlayerCharacter === false` **or no player owner** (`countsAsNpc`; the GM-only "PJ" checkbox in the sheet header sets the flag, which had no UI before) — dies directly: core defeated status + `combatant.defeated`. Anything that lifts Vida above 0 (regeneration, heal) turns Caído into **Inconsciente** for `wakeRounds` more turns; after that he acts. Both conditions (and any catalog Condition with `incapacitates`, plus the core "dead") **incapacitate**: `blockIfIncapacitated` refuses Skill use (`useSkillEffect` + the sheet before prompting), weapon attacks, using a consumable *by* him (an ally can still use one *on* him), Correr (sheet + `setMovementDash` relay) and Token movement (`preMoveToken`, GM exempt); entering one switches off every Active Skill (`createActiveEffect` → `shutdownActiveSkills` in upkeep.js, generalized from the Mana-0 shutdown). **What the body does keeps working** — natural/Title/Species regeneration, periodic heals, heals from others — like Regeneration in D&D (troll) and Pathfinder; the heal blocks (Fogo/Ácido) are what keep a regenerator down. **Mana does not regenerate** while incapacitated (`tickRegeneration` zeroes the energy part — keeping Mana up is an action), only Vida. **Dead** (core defeated status, `isDead`) processes nothing on its turn — no zone tick, periodic tick, regeneration, upkeep or curse (`updateCombat` guards each step with `dead`) — except advancing the Zones *it* cast and `processPendingUpkeepRemoval`, which must still run so the buffs its Active Skills gave allies disappear. Counters live in the effect flag `incapacitation` and tick at the start of the character's own turn (`tickIncapacitation`, designated GM, called first in `updateCombat`, before zones/ticks/regeneration), not by Foundry duration (V14 only *suppresses* an expired effect). Damage-card Desfazer passes `nihilityUndo` (the fall is reverted entirely, killed NPC un-defeated via the `killedAtZero` flag); Descanso passes `nihilityRest` (wakes fully — out of combat there are no turns to count). Marking Caído/Inconsciente by hand on the Token skips the value dialog; a hand-marked Inconsciente has no counter and stays until the GM removes it. Saved Condition catalogs get both via the `incapacitationConditions` migration.

**Contágio** (`module/combat/contagion.js`, pure rules in `contagion-rules.js`, tested; 1.71.0): a catalog Condition with `spread: {chance, radius, immuneTraits}` (edited in the Condition card editor; factory example "Praga") spreads at the **start of its carrier's turn** (`tickContagion`, designated GM, from `updateCombat` after the Vida-0 tick, never for the dead): every Personagem with a Token on the carrier's scene within `radius` metres (token centre to centre, `tokenDocCenter`/`sceneScale`), not dead and without the Condition, rolls a d100 against `contagionChance` — 0 with a listed Trait (`actorTraits`), reduced proportionally by the best chained Resistance to the Condition's `elements` (same `resistanceSourceFor` + `damageElementChain` + `chainedResistance` as damage; 100% = immune). Catching applies the Condition with its **default effect** (like "usar o efeito padrão" on the Token), or just the marker if it has none. One chat card per spreading Condition lists who caught / resisted with the roll; whispered to the GM if any Token involved is hidden. Only in combat (it needs turns). Validar Mundo checks the `immuneTraits` references.

**Ambiente da cena e densidade de mana** (`module/environment/environment.js`, pure rules in `environment-rules.js`, tested; `FEATURES.environment`, on; 1.72.0): two sources. The **scene** keeps `flags.<system>.environment = {hazards: [{conditionId, immuneTraits, fx}], manaDensity, fxPlaying}`, edited in `apps/environment-config.js`, one window per scene (`nihility-environment-<sceneId>`, no scene dropdown — a world has dozens of scenes): the menu row (Configurações Gerais → Combate e Dano → Ambiente da Cena) opens the scene on the canvas, and right-click on any scene in the Scenes sidebar → "Ambiente (Nihility)" opens that one (`registerEnvironmentSceneMenu`, `getSceneContextOptions` with both the V14 `visible`/`onClick` and V13 `condition`/`callback` keys). **Areas** are Foundry Regions with the system Region Behavior `nihilityEnvironment` (declared in `system.json` `documentTypes.RegionBehavior`, label `TYPES.RegionBehavior.nihilityEnvironment`; schema `conditions`/`immuneTraits` SetFields + nullable `manaDensity`; the config window is Foundry's own). A hazard is a catalog Condition kept on every Personagem inside, except those with a listed Trait: `syncTokenEnvironment` (designated GM, queued per actor uuid so concurrent triggers can't double-create) diffs `desiredEnvironmentConditions` against the effects flagged `environment: {sceneId}` (`environmentDiff` — a Condition the actor already has from another source is neither duplicated nor removed), applies new ones with the Condition's **default effect** (`applyManualCondition`), then clears their duration and, for periodic ones, anchors them to `environment:<sceneId>` with `ticksRemaining: 0` (shows "até desativar"). Triggers: `createToken`, `deleteToken` (`leaveScene`, linked actors), scene flag change, Region/behavior create/update/delete, Region events TOKEN_ENTER/TOKEN_EXIT, Trait/Species changes (`updateActor`) and the start of each combatant's turn (`updateCombat`, before the round ticks). **Mana density**: `manaDensityFor(actor)` = `resolveManaDensity` — the **lowest** of the areas the token is in, else the scene's, else the world setting `manaDensityDefault` (Regras da Mesa, default 1); always 1 with the feature off. **Mana interna (owner's decision, 12/11):** density never blocks or weakens a cast — the caster spends their own Mana. For a Skill where `isMagicUse` is true, `useSkillEffect` multiplies `mech.investPower` by `castPowerFromDensity(density)` = `max(1, density)` (pure, tested: dense mana still boosts damage, effects and Structure HP; rarefied or 0 changes nothing). What density 0 stops is a magic **Active** Skill being *sustained*: switching one on there is refused (`densitySustainsMagic`), and `tickActorUpkeepSkills` switches off every magic Active Skill of a holder standing at density 0 before charging upkeep, through `deactivateUpkeepSource` (effects released, structures follow the Vida-1/vanish rule), with one chat line. Only Antimagia blocks a cast; `tickRegeneration` multiplies the energy regen % by it, and "De onde vem" shows the factor. Cost and Active-Skill upkeep are untouched on purpose (owner's choice). **FXMaster** (optional, `relationships.recommends`): each scene hazard has a "Visual" row — a ready preset (`fx`, `FXMASTER.api.presets`, labels from `fxPresetLabel`) and/or a particle + filter from FXMaster's own registries (`fxParticle`/`fxFilter`, read from `CONFIG.fxmaster.particleEffects`/`filterEffects`, so FXMaster+ types appear by themselves) with an optional colour (`fxColor`, written to the effect type's first `type: "color"` parameter — `tint` on particles, `color` on the Color filter; options start from the class `default`). `wantedSceneFx`/`sceneFxPlan` (pure, tested) diff what the hazards want against the stored `fxPlaying` (`{preset}` or `{key, ids}`; plain strings = old presets): `syncSceneFx` stops presets by name and combinations by the ids `FXMASTER.api.effects.play` returned, plays only what is new and leaves what continues untouched. Areas don't need this: FXMaster's own Region behaviors ("FXMaster: Particle Effects"/"Filter Effects") go on the same Region. Without the module the row is hidden and a hint says what it would add.

**Radiação** (`module/environment/radiation.js`, pure rules in `radiation-rules.js`, tested; `FEATURES.radiation`, child of `environment`, on; options `radiationGainPercent` 20, `radiationDecayPercent` 10, `radiationDamagePerLevel` 1; 1.73.0). Designed with the owner: a place has a radiation **level**; whoever stays there is **irradiated** up to that level, and the damage per round grows with the irradiation (fixed points per level, on purpose — a long stay near a strong source deals thousands in one turn); outside, irradiation and damage fall. Sources **add up** (`totalExposure`): the scene (`radiation` in the scene environment flag, field in the Ambiente da Cena window), Regions (`radiation` on the `nihilityEnvironment` behavior), and Tokens that emit (`flags.<system>.radiationSource = {level, radius}`, set through the GM-only ☢ button the `renderTokenHUD` hook adds to the Token HUD; `emitterExposure` falls linearly from full at the centre to 0 at the radius; a Token never irradiates itself). `radiationStep`: below the place's level it rises `gain%` of the **place's level** per round (a strong source irradiates faster, min 1) up to it; above, it falls `decay%` of the **current irradiation** (min 1) down to it. Damage = `radiationDamage(level, perLevel)`, straight to Vida (like a tick, no Escudo), reduced by Resistência Geral and by Resistance to the `radiation` element when the catalog has it (`RADIATION_ELEMENT` in the Sci-Fi defaults; migration `radiationElement` appends it to a saved catalog that already holds Sci-Fi elements). Irradiation lives in one Active Effect "Irradiado (N)" (flag `radiation.level`, status `irradiated`, `icons/svg/radiation.svg`); level 0 deletes it, and the GM deleting it is the cure. In combat `tickRadiation` runs at the start of each Personagem's turn (`updateCombat`, after the environment sync, not for the dead); out of combat the window's **"Passar tempo…"** (rounds/minutes/hours, `CONFIG.time.roundTime`) runs `simulateRadiation` for every Personagem on the scene at once (`passRadiationTime`) and whispers the GM a summary. Designated GM / GM only.

**Condições no HUD do token** (`module/combat/conditions.js`): the Condition catalog (`getActiveStatusConditions()`) also feeds `CONFIG.statusEffects`, so the GM can click a token and mark "Envenenado" by hand — the natural Foundry gesture — instead of reaching it only from inside a Skill. It **replaces** the core list rather than concatenating: core ships dozens of statuses from other systems (prone, invisible, dead…) that mean nothing here, and mixing them would fill the palette with icons backed by no rule. `defeated` is the one exception, preserved because Foundry itself uses it to mark a defeated combatant — and it's looked up in the saved core snapshot, not in the live `CONFIG.statusEffects`, so re-publishing after a catalog edit doesn't silently drop it.

`interceptManualCondition` (on `preCreateActiveEffect`) has to **cancel** the creation and recreate it afterwards: the hook is synchronous and can't await a dialog, so the original document dies there and `options.nihilityConfigured` on the second pass is what prevents an infinite loop. The dialog is all-optional — with no Alvo and no Valor the Condition is just the icon on the token, which is the most common case at the table ("he's blind", "he's stunned"), where the GM adjudicates the effect and the system only carries the marker. Both routes (Skill and GM's hand) end in the **same** `applyEffectsToActor`, so a hand-marked Condition stacks with the same Condition arriving from a Skill instead of becoming a second independent effect.

Both `registerStatusConditions()` and `interceptManualCondition` are gated on `isStatusConditionsEnabled()`. This matters more than the usual toggle: with the block off, an ungated `registerStatusConditions()` would leave the world **with the Nihility palette and without the core's statuses** — turning a feature off would be adding UI rather than hiding it, the exact inverse of the rule. When the block is off the saved core list is restored, so flipping the toggle at runtime is reversible like everything else.

**Números flutuantes sobre o Token** (`module/combat/floating-numbers.js`, rule in `combat/vital-deltas.js`, pure/tested): the table is narrated by voice and players watch the map, not the chat, so Vida/Escudo/Mana changes (ship: Escudo/Casco/Integridade) rise from the Token as colored numbers — red damage, green heal, blue Escudo, purple Mana, amber Casco; Vida shows only the number. Each client remembers the last value of every Actor with a drawn Token (`drawToken`) and compares on `updateActor` — deliberately **not** `preUpdateActor`, whose old value exists only on the writing client and whose path differs for unlinked tokens (ActorDelta). That makes every writer show up (Aplicar, ticks, regen, rest, Desfazer, hand edits) without touching any of them. Players see the exact number (the dice are public anyway; only the reductions are hidden). Mana shows only to the owner and the GM; hidden/secret Tokens only to whoever sees them (same test as the core). Conditions entering/leaving are **not** ours: the core already floats `+(Envenenado)`/`−(Envenenado)` (`ActiveEffect#_displayScrollingStatus`). Off switches: the client setting `floatingNumbers` (just this browser), and the core world setting "scrolling status text", which gates `createScrollingText` itself.

**Avisos na tela (1.74.0; mockup approved by the owner: Design artifact "Avisos na Tela", boards 2–4 — boards 1/1B, a turn-start banner, were rejected as visual noise; the owner already uses a module that shows whose turn it is).**
- **Voz do Mundo na tela** (`module/core/voice-banner.js`): every Voz do Mundo announcement also shows as a gold card at the top-centre of the screen of whoever is in its `whisper` (owner + GMs), read in each client's `createChatMessage` — no socket. `announceVoiceOfTheWorld` now also stores `title`/`body` in the message flags; the body becomes plain text (`textContent`, never injected HTML). One card at a time (queue, max 6), ~6 s or click. Client setting `voiceBanner`.
- **Duração sobre os ícones do Token** (`module/combat/effect-badges.js`, rule `effect-badge-rules.js` pure/tested): a number in the corner of each effect icon — yellow rounds/ticks left, cyan ∞ until the Active Skill is switched off, lime the radiation level, red the Caído/Inconsciente counter; nothing for effects with no deadline (Ambiente, Maldição, hand-marked). **Only on Tokens the user owns; the GM sees all** (owner's decision). A Token subclass chained onto `CONFIG.Token.objectClass` (after movement.js's) overrides `_drawEffects`/`_refreshEffects`: icons are matched to effects through the `zIndex` the core writes (= position in the shown list; if that mapping isn't clean, nothing is drawn rather than a number on the wrong icon), and the numbers live in a separate container because the core's `_refreshEffects` treats every child of `effects` as an icon. Foundry durations are read from `duration.remaining` only when counted in rounds/turns (V14 `units`, V13 `type`). Refreshed on `updateActiveEffect` and every `updateCombat`. Client setting `effectBadges`.

**Fim do combate (backlog L11 + H11, 1.75.0; mockup approved by the owner: Design artifact "Fim do Combate", board 1, opened by option A of board 2).** `module/apps/end-combat.js`, pure rules in `combat/end-combat-rules.js` (tested); `FEATURES.endOfCombat`, on, option `combatXpPercent` 25. When the GM ends a combat that got past round 0 with Foundry's own "Encerrar combate", `deleteCombat` (only on the client of the user who deleted it, GM only) reads the deleted document's combatants (`summarizeCombat`) and opens one window: **effects still running** per character — those `endCombatEffectChoice` lists from the Token badge (`badgeFor`): finite rounds/ticks come checked (= removed on Concluir, they would freeze out of combat), the Caído/Inconsciente counter comes unchecked (the GM decides), nothing without a deadline (Maldição, Ambiente, Active Skill) is listed; **XP do combate** — `suggestCombatXp` = Σ over defeated NPCs (`countsAsNpc` + defeated/dead) of `combatXpPercent`% of `getXpForNextLevel(level)`, `splitXp` among the PCs who fought, each part editable (changing the total re-splits; changing one part leaves the others), written to `system.attributes.xp` and announced through Voz do Mundo (`kind: "xp-gain"`; the cap/xp-ready logic stays the usual one); **Descanso curto para todos os PJs** (unchecked; `applyShortRest`, newly exported from regeneration.js, same rule as the sheet's Descansar). "Pular" closes without doing anything.

**Desfazer uso de Skill (backlog L12, 1.76.0; mockup approved by the owner: Design artifact "Desfazer Uso de Skill", boards 1–2).** `module/skills/skill-undo.js`, pure rules in `skills/skill-undo-rules.js` (tested), use context in `skills/skill-use-context.js` (no imports on purpose — structures.js and area-effects.js read it); `FEATURES.skillUndo`, on. Owner's decisions: **only the GM** undoes; **until the user's turn ends** (in a started combat the button lives while `combat.round`/`turn` equal the ones at use time — `undoWindowOpen`; out of combat, while it is that character's latest recorded use); **applied damage comes back too** (the damage card's own undo, `undoDamageCard`). `useSkillEffect` is now a wrapper: `recordSkillUse(sourceActor, skillId, options, run)` **photographs** the user and every target (`options.targetActor`/`targetActors`) before and after the use — vitals from `_source` (`UNDO_VITAL_PATHS`: Vida/Mana/Escudo; ship Escudo/Recarga/Bateria — Casco/Integridade are Módulo HP), Escudo pools, every Active Effect's `toObject()`, tracked Item fields (`UNDO_ITEM_PATHS`: active, xp, hp.value, integrity, lost, status, plus Sub-Skill `active`s) and the `sustainedShields`/`shipEffects` flags — and stores only the difference (`diffFields`/`diffEffects`) in the use's card flag `skillUse` (the last message the user created during the use; a tiny "X usou Y" card if there was none). Deactivating an Active Skill is never recorded. While the use runs, every chat message this user creates gets `skillUseId` (`preCreateChatMessage`, Voz do Mundo excluded) and a Estrutura/Zona requested from the GM carries `useId` (structure instance / zone flag). Undo (`performSkillUndo`): damage cards of the use undo their applied hits → per actor, created effects are deleted, changed ones restored with `recursive: false`, deleted ones recreated (`keepId`, `nihilityConfigured`) → Items reverted → vitals by **difference** (`revertFields`: current − (after − before), so whatever else happened meanwhile stays) and pools by `revertPools` → flags restored → Estruturas/Zonas with that `useId` removed → every card of the use flagged `skillUndone` (struck through, "Uso desfeito pelo Mestre" strip; damage controls no longer drawn). Confirmation lists `undoPreviewRows`. Not reverted: damage a Estrutura took from the use (relay bookkeeping) and Resistance XP the GM relay credited to a target after the use ended. Uses made before 1.76.0 have no record and no button.

**Deslocamento por rodada** (`module/combat/movement.js`, rule in `config.js`, derived value in `character-model.js`): behind `FEATURES.movement` (**off by default** — turning it on changes how tokens behave in combat, and existing worlds must not get a new rule just by updating). Total = `min(base + ⌊Destreza.total ÷ passo⌋, teto) + trunc(Destreza.buffDelta ÷ passo)` (`movementAllowance`, pure, tested): the **permanent** part (points + Title, i.e. `total`) is capped; the **Skill** part (`buffDelta`, temporary effects) is added on top with **no cap** and goes negative when a Skill lowers Destreza. Base 6 m / passo 10 / teto 18 m by default, all editable in *Módulos do Sistema*; Item bonuses stay out, like everywhere else. `deriveMovement()` puts the result in `system.movement` (never saved), and the Destreza row of the sheet shows it as a chip (`describeMovement`) — there is deliberately **no** used/remaining bar on the sheet: the spent amount shows on the token ruler label ("gasto / máximo").

The enforcement was designed from a probe run in a real Foundry V14 (the probe is gone; don't reintroduce a global limiter without re-checking these facts): a `Token` subclass (chained onto `CONFIG.Token.objectClass`) overrides `constrainMovementPath` — the same hook the core uses to cut a path at a wall — returning `[waypoints, true]` cut at the remaining budget, so the drag stops there and the ruler draws the excess dashed **on its own**; `preMoveToken` returning `false` is only a safety net (it is all-or-nothing, waypoints can't be changed there); cost comes from `movement.passed.cost`, in scene units. Rules: it only limits in a **started** combat and only for combatants (out of combat the token is free — an early version limited everywhere and left tokens stuck with no way to reset); spent metres live in the Combatant flag `movementUsed`, read synchronously by every client while dragging and written only by the designated GM from the `moveToken` hook (~20 ms to arrive); it resets in `updateCombat` when that combatant's own turn begins, so leftover metres can be used off-turn and someone who spent everything stays put until their turn; the GM is exempt (and what the GM moves isn't counted) when `movementGmIgnores` is on. **Correr** doubles the turn's allowance: the `movementDash` Combatant flag, toggled from the sheet header button (only during the character's own turn, via the `setMovementDash` relay action, which re-validates that the combatant really is the current turn), reset together with the spent metres. It costs nothing in the system — the table judges the action spent.

**Nave/Veículo use the same engine** with `system.movementCells` (behind `FEATURES.shipManeuver`, also off by default): `floor(base of the Porte × engine ratio)` cells, converted to scene units by `scene.grid.distance` so a space scene with its own grid scale works. The **engine ratio** (`engineRatio`, pure) is the installed Motor's *effective* Aceleração/Rotação (throttle, energy starvation and Motor HP already applied) divided by the reference of the Motor the ship's Porte asks for (Mini→Compacto … Capital→Colossal in `MODULE_SIZE_PRESETS.engine`): using the raw Aceleração would make a Capital ship 16× faster than a Mini one, because Motor stats double per size. `system.evasion` (0–1) is `min(evasion base of the Porte × Rotação ratio, cap)`, and `applyStarshipDamageCascade` applies it first — before Penetração, Escudo and Casco — and only while the block is on. The per-Porte cells/evasion live on each Porte row (`move`/`evasion`); the cap is the `shipEvasionCap` option of the `shipManeuver` feature. A ship without a Motor has 0 cells and 0 evasion.


- **Sessão 4 (1.103.1):** `Combat.rollAll()` não falha mais em quem não tem o atributo de iniciativa (`safeInitiativeFormula`, cai em 0). **Limite conhecido:** números flutuantes de fontes diferentes no mesmo Token (os nossos de Vida/Mana e o texto de Condição do core, "Fúria do duelo: Destreza +11" e "Inconsciente") saem juntos e se sobrepõem; só os nossos são escalonados (350 ms entre si). Usar uma Skill de Estrutura sem cena aberta avisa na tela que a Estrutura não foi criada.
